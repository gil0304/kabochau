# PUMPKIN ME 🎃

あなたの顔が、光るジャック・オー・ランタンに。

- **LIVE** — インカメラ映像の **頭全体（あご・耳・髪まで）を覆う** 3Dカボチャ（パンプキンヘッド）をリアルタイムで重ねる。頭の位置・大きさ・向き（ヨー/ピッチ/ロール）に追従し、彫刻の目・鼻・口は本人の目・鼻・口の位置に合わせたまま、まばたき・笑顔・口の開閉・眉の動きが彫刻の形と発光に反映される。
- **MAKE**（顔からつくる）— 撮影した顔（またはアップロード写真）の目の間隔・形・傾き、眉の角度、鼻と口の比率、左右差を測定し、その人だけのカボチャを3Dで彫刻する。完成画像に人物写真は含まれない。
- **複数人** — LIVE / MAKE とも最大4人（低性能端末は2人）まで同時に対応。LIVE は一人ひとりに自分の表情で動くカボチャ、MAKE は一人ひとりの顔から別々のカボチャを彫り、並べて1枚にする。グループ写真からも作れる。
- **スタンプ** — 結果画面でハロウィンのスタンプ（文字・おばけ・コウモリ・黒猫など15種）を貼って移動・拡大・回転し、スタンプ入りの PNG を保存 / 共有できる。

> 旧名 CARVE。画面上の名前は MAKE に変更したが、コード内部の識別子（`mode === 'carve'`、`CarveStage`、`CARVE_STYLE` など）は互換のため carve のまま。

Nuxt 4 + TypeScript + Three.js + MediaPipe Face Landmarker。顔の解析はすべてブラウザ内で完結し、画像・ランドマークは一切送信しない。

## 2. 使い方

1. 「カメラをはじめる」→ カメラを許可。
2. 下部の **LIVE（顔にかぶる）/ MAKE（顔からつくる）** で切り替え、丸いボタンで撮影。
   - LIVE: その瞬間の「カメラ映像 + カボチャ」を 1080×1920 PNG に書き出し、プレビュー表示。
   - 複数人が映ると全員がそれぞれのカボチャをかぶる（「N人をカボチャに変身中」と表示）。MAKE では「ボタンでN人それぞれのカボチャをつくります」と表示され、全員分を一度に彫る。上限（4人、低性能端末は2人）を超えると大きく映っている人が優先される。
   - MAKE: 直近数フレームの顔特徴を平均して確定 → 暗闇 → シルエット出現 → 目・鼻・眉・口を順に彫刻 → 点火 → 完成。タップ / 「スキップ」で演出を飛ばせる。完成後はドラッグ（または ←/→ キー）で回転し、彫りの深さを確認できる。カボチャ表面は指の動きと同じ方向に回る（右へドラッグ → 正面が右へ向く）。
3. 「スタンプでデコる」→ 下のトレイからスタンプをタップして追加（最大24個）。
   - ドラッグで移動、2本指ピンチで拡大縮小＋回転、選択枠右下のつまみでも拡大縮小＋回転（マウス向け）。マウスホイールで拡大縮小、Shift/Alt + ホイールで回転。
   - キーボード: スタンプにフォーカスして 矢印=移動、+/-=拡大縮小、[ / ]=回転、Delete=削除。
   - 選択中のスタンプは × ボタンまたは下の「削除」、「すべて消す」で全削除。「完了」で編集を終える。
   - MAKE ではスタンプ編集を始めると、保存されるPNG（完成ポーズ）の上で編集する（3Dの回転表示から静止画に切り替わる）。
4. 「保存」で PNG をダウンロード（スタンプがあればスタンプ入り）。共有に対応する端末では「共有」（Web Share API、ボタンを押したときだけ）。「撮り直す」でカメラに戻る（スタンプも消える）。
5. カメラが使えない場合は 🖼 ボタン / 「写真からカボチャをつくる」で写真を選ぶと MAKE を生成する。グループ写真なら写っている人数分（上限まで）のカボチャを、写真の左から右の順に並べる。写真のピクセルは解析後すぐ破棄し、パラメータだけを使う。

### データの流れ
```
camera <video> ─▶ FaceLandmarker.detectForVideo (最大4顔)
   └─▶ FaceTrackMatcher (人物ID) ─▶ 人物ごとに ↓（フィルタ・カボチャも人物ごと）
   └─▶ normalizeLandmarks (display空間, face frame)
         ├─▶ One Euro 平滑化 ─▶ computeFaceParams ─▶ deriveExpression
         │         └─▶ buildCarveLayout(LIVE_STYLE) ─▶ PumpkinModel.setCarving   (LIVE)
         ├─▶ facePose (アンカー・顔幅・回転) ─▶ coverCrop ─▶ カボチャ配置          (LIVE)
         └─▶ 直近フレーム平均 ─▶ MAKE: pumpkinShapeFromParams + buildCarveLayout(CARVE_STYLE)
写真 ─▶ detect (IMAGE, 全体 + 足りなければ重なりタイル) ─▶ 重複統合 ─▶ landmarksToParams(mirrored=false) ×人数 ─▶ MAKE
```

### 複数人対応
- **人物の対応付け（LIVE）**: MediaPipe は顔を順不同で返すため、毎回の検出を `FaceTrackMatcher` で既存の人物に対応付ける。コスト = 顔の中心の移動量（顔幅単位）、顔の大きさが半分〜2倍の範囲だけ同一人物とみなし、小さい順に貪欲に割り当てる。0.8 秒見失った人物は忘れる。上限を超える顔は大きい順に採用。人物ごとに One Euro フィルタ・姿勢・表情・カボチャを持つので、並び順が入れ替わってもカボチャが別人に飛ばない。
- **カボチャの奥行き（LIVE）**: 顔が大きい（近い）人ほどカボチャを手前に置き、同じ比率で拡大する（`liveFaceDepth`）。画面上の位置と大きさは変わらず、重なったときに手前の人のカボチャが前に描かれる。
- **カボチャは最初から上限数ぶん作っておき**、使わないものは非表示にする（ろうそくの点光源はシーンに残したまま強度0）。人が出入りしても点光源の数＝シェーダの種類が変わらず、途中でシェーダの再コンパイルによる引っかかりが起きない。
- **ろうそくの光の分離**: 影のない点光源のため、そのままでは隣のカボチャの皮や中身まで照らしてしまう。外皮は点光源を受けず、中身と切断面は「自分のろうそく」（ビュー空間の位置で照合）だけを受ける。
- **MAKE の配置**: 書き出しが縦長 9:16 のため横一列にすると全員が小さくなる。前列は最大2つ、3〜4人のときは残りを後ろの干し草（手続き的テクスチャ）の上に載せ、後列の口が前列のカボチャとヘタより上に来る高さにする。人物の左右の並び（プレビュー/写真で見た順）は保つ。彫刻は 0.14 秒ずつずらして順番に彫り、全員彫り終わってから一斉に点火する。カメラは全体のバウンディングボックスが収まる距離（縦長では横幅基準）で、霧の濃さは距離に応じて薄める。
- **書き出しの構図（LIVE）**: プレビューに映っている人のカボチャが 9:16 に収まるようにずらす。人の顔そのものが 9:16 に収まらない場合（横長の Web カメラで横並びなど）は、誰かを切るかわりにズームアウトし、カメラ映像の外側はぼかして暗くした映像で埋める（ストーリー形式）。カボチャがフレームの端からはみ出しているだけではズームアウトしない。
- **グループ写真**: 短距離顔検出器は画像全体を 128px に縮小するため、集合写真の小さい顔を見落とす。写真では全体で見つかった顔が上限未満なら、25% ずつ重ねたタイル（横長は2〜3列、縦長は2段、正方形に近ければ2×2）でも検出し、全体座標に戻して重複を除く（タイルの内側の境界で切れた顔は捨てる）。

### 座標系と符号規約
1. **MediaPipe 空間**: x,y ∈ [0,1]（ミラー前の元画像、y 下向き）、z は x と同スケールの相対深度（小さいほどカメラに近い）。
2. **Display 空間**（ユーザーが見ている向き）: セルフィーは左右反転 `xd = 1 − x`。ピクセル単位で `X = xd·W, Y = −y·H, Z = −z·W`（右手系・y上向き = three.js のカメラ空間と同じ）。**`left` / `right` は常に画面上の左右**であり、本人の解剖学的左右ではない。
   - ミラー時（カメラ）: 本人の左目 = 画面左。非ミラー時（写真）: 本人の右目 = 画面左。
   - MediaPipe のブレンドシェイプ `eyeBlinkLeft` 等は本人基準なので、同じ規則で画面左右に変換する。
3. **Face frame**: 原点 = 両目中心の中点、x̂ = 対称ランドマーク8組（目尻・目頭・頬・口角・眉・顎・小鼻）の平均差分（画面左→右）、ŷ = 顎→額を x̂ に直交化、ẑ = x̂×ŷ（正面の顔で手前向き）。単位 = 3D 顔幅（頬 234↔454）。平行移動・拡大・ロールに対して不変（テストで 1e-4 以内）、ヨー/ピッチにもほぼ不変。
4. **カボチャ物体空間**: 中心原点、+x 画面右、+y 上、+z 手前（彫刻面）、半径 ≈ 1。face frame の (u,v) は `anchorY·radiusY + v·faceScale` で写像。
   - **LIVE（頭全体を覆う）**: canonical face の比率（あご ≈ −0.79、頭頂 ≈ +0.72、耳込みの頭幅 ≈ 1.15、単位は顔幅）から、カボチャの半幅 = 顔幅 × `LIVE_HEAD_SCALE`(1.08)、中心 = 目の高さ + `LIVE_HEAD_CENTER_Y`(0.03)、やや縦長の `LIVE_PUMPKIN_SHAPE`（radiusY 0.93）とした。あごから髪の上端まで覆い、カボチャ幅は顔幅の約2.2倍。彫刻は `faceScale = 1/LIVE_HEAD_SCALE` で実際の目・鼻・口の位置に一致させ、カボチャ表面上の「両目の中点」を追跡中の両目中点に固定して配置する。
   - LIVE の描画カメラは画角 16°（ほぼ平行投影）。カボチャの中心は固定点より顔幅1つぶん奥にあるため、広角だと輪郭が15〜20%小さく映り、あごや髪が覆い切れなくなる。
5. **画面への写像**: プレビューも書き出しも `coverCrop(動画, 出力サイズ)` の同じ関数で決まる矩形を使い、カメラ映像はシェーダ内で UV 変換（ミラー含む）して描画する。CSS の `object-fit` や `transform: scaleX(-1)`、devicePixelRatio は計算に入らないため、解像度を変えても位置ずれが起きない。
6. **平滑化**: 顔ランドマーク（face frame 座標）と姿勢（アンカー・顔幅・軸ベクトル）に One Euro フィルタ。さらに描画フレーム間を時定数 30ms で補間（推論 < 描画レートでも滑らか）。まばたきは閉じる方向だけ速く追従。顔を 0.6 秒以上見失った後はフィルタをリセットしてスナップ。

### 彫刻の実装方法（CSG は使わない）
- 殻は放射関数 `ρ(θ,φ)`（楕円体 × 縦溝 × 上下のくぼみ × 下ぶくれ × 個体差のゆらぎ）のパラメトリックメッシュ。法線は解析的（差分）に計算。
- 各パーツのアウトラインを **GPU でマスク画像に描画**し、外皮と内側（同じメッシュの裏面）の前半分で該当ピクセルを `discard` → 実際に向こう側が見える穴になる。
- 同じアウトラインを外皮表面から内側へ放射方向に押し出した **切断面メッシュ** を毎回生成（LIVE は最大約30Hz で更新）。外縁は皮の色、奥ほど強く発光するグラデーション。
- 穴から見える内側は、ろうそく位置からの距離減衰つき発光 + 点光源 + 炎スプライト。穴の周りの皮にはマスクのミップマップぼかしで光の滲み、ブルームでハロ、ふたの切れ込み（ジグザグ）も発光。
- ろうそくの点光源は外皮を直接照らさない（殻の内側にあり、影なし点光源だとバンプで傾いた法線が照らされて側面の溝に光の筋が出ていたため。穴の周りの光は上の発光で表現）。中身と切断面は自分のろうそくだけで照らす（複数人対応の項を参照）。ふたの切れ込みの発光は分岐なしの式で計算する（`fwidth` を条件分岐内で評価すると y=0.25 の高さに点線状の光る輪が出ていた）。
- メッシュブーリアンを使わないため毎フレームでも安定。ただし「殻の厚み」は切断面（厚さ ≈ 0.09）で表現しており、穴の外側にある殻自体は厚みゼロ。

### MAKE の個人化
`PumpkinFaceParams` から次を決める（canonical face を平均顔とし、そこからの差を MAKE では 1.9 倍に誇張）:

| 顔の測定値 | カボチャへの反映 |
| --- | --- |
| 目の中心位置・間隔・幅・開き・目尻の傾き・上まぶたの頂点位置・上下比 | 目の穴の位置・大きさ・高さ・傾き・アーモンド↔三角の形 |
| 眉の内端/外端/アーチ・角度・目からの高さ | 眉の切り込みの位置・角度・カーブ（怒り眉/困り眉） |
| 鼻の幅・長さ・鼻先の偏り・小鼻の傾き・鼻の高さ | 鼻の三角の幅・高さ・頂点位置・底辺の傾き/くぼみ |
| 口の幅・中心・口角の高さ（左右別）・開き・唇の厚み | 口の幅・笑いのカーブ（左右非対称）・開口の厚み・歯の本数と位置 |
| 顔の縦横比・あご幅・額の高さ | カボチャの縦横比・下ぶくれ・上のくぼみ・ヘタの長さ |
| （上記の数値ハッシュ） | 縦溝の本数（8–12）・溝の深さ・ゆらぎ・ヘタの曲がり |

撮影時の表情（笑顔・口の開き・まばたき）も反映される。テストでは7種類の合成顔すべてが互いに異なる彫刻になること、目の間隔・口幅・眉の角度などが期待方向に変化することを検証している。

## 4. プライバシー / セキュリティ
- カメラ映像・写真・ランドマークはブラウザ内でのみ処理。サーバーへのアップロード、アカウント、DB、アナリティクス、外部画像生成APIは無し。
- 本番ではレスポンスヘッダで `Content-Security-Policy: connect-src 'self' blob: data: https://cdn.jsdelivr.net https://storage.googleapis.com`（モデル取得のフォールバック先のみ許可）、`Permissions-Policy: camera=(self), microphone=()` を付与。万一コードが外部に送信しようとしてもブラウザが遮断する。
- 写真は解析直後にキャンバス（タイル検出用の一時キャンバスも）を解放し、MAKE には数値パラメータだけを渡す。完成画像に元の写真は入らない。
- 保存は blob URL のダウンロード、共有はユーザーがボタンを押したときの OS 共有シートのみ。

## 5. 書き出し仕様
- 既定 **1080×1920 PNG**。GPU の最大レンダーバッファが足りない端末・低性能ティアでは **720×1280** に明示的にフォールバックし、結果画面に表示する。
- LIVE: プレビューと同じ合成パイプライン（カメラ + カボチャ + ブルーム + ビネット）を書き出しサイズで再描画。UI（ボタン・ヒント）は含まれない。9:16 のクロップはプレビューの中心を基準に、プレビューに映っている全員の顔とカボチャがはみ出さない範囲でだけずらす。顔が収まらない人数・配置のときだけズームアウトし、余白はぼかした映像で埋める（そのときはブルームも弱めて見た目を揃える）。
- MAKE: カボチャ全体（ヘタ含む、複数人なら全員と干し草）が 9:16 に収まるようカメラ距離を計算し、完成ポーズで描画。
- スタンプ: 位置・大きさ・回転は書き出し画像に対する正規化座標（中心 x,y ∈ [0,1]、幅は画像幅比、回転は時計回りラジアン）で保持し、保存/共有時に端末内の 2D キャンバスで元PNGの上に合成する（同じ解像度の PNG）。エディタは同じスタンプ定義を SVG で描くため、画面と保存結果が一致する。画像ファイルは使わず、外部への送信もない。編集のたびに 0.4 秒後に裏で合成しておき、「共有」がユーザー操作の有効期限内に呼べるようにしている。

## 6. パフォーマンス / 堅牢性
- 描画は requestAnimationFrame 1本。推論は「新しい動画フレームがあり、かつ前回推論コスト×1.25 以上経過」したときだけ（最大 ~11fps まで間引き、間は補間）。
- 品質ティア（端末メモリ/コア数/ポインタ種別）で DPR・MSAA・ブルーム・メッシュ密度・同時人数（high/medium 4人、low 2人）を決定し、LIVE ではフレーム時間が続けて 30ms を超えると DPR → ブルームの順に自動で下げる。
- タブ非表示中はループを停止。iOS でカメラトラックが終了した場合は復帰時に再取得。
- アンマウント時に GPU リソース・WebGL コンテキスト・rAF・ResizeObserver・カメラトラックを解放。
- WebGL コンテキスト消失・WebGL 非対応・カメラ拒否/未接続/使用中・HTTP 接続・モデル読み込み失敗・写真に顔なし・書き出し失敗は、それぞれ再試行/写真入力/再読み込みの導線つきで表示。

## 8. 既知の制限・トレードオフ
- 穴の「殻の厚み」は切断面メッシュで表現している（CSG で殻ごと刳り抜いてはいない）。穴の縁から少し離れた位置の殻は厚みゼロ。
- MediaPipe の短距離顔検出器は画面全体を 128px に縮小して検出するため、**顔が画面に対して小さい（横長カメラで顔幅 2割以下程度）と検出されにくい**。その場合「少し近づいてください」と表示する。複数人の自撮りでは全員がこの大きさ以上で映る必要がある（偽カメラで4人を横一列に並べた映像では2人しか検出されなかった）。写真はタイル検出で補うが、カメラ映像では毎フレームのタイル検出は重いため行っていない。
- 人物の対応付けは位置と大きさだけで行う（顔認証はしない）。2人が完全に重なる・0.8 秒以上隠れる・画面外から別の人が同じ位置に入る、といった場合は人物IDが入れ替わる／振り直されることがある（カボチャは表情とともにすぐ追従し直す）。
- 4人同時は推論（1人ごとにランドマーク推定）と描画（カボチャ4つ）の負荷が増える。推論は既存の適応間引き、描画は負荷ガバナーで下げるが、実機の発熱下での挙動は未検証。
- 横向き/上向きが大きい顔（±45°超）ではランドマークの精度が落ち、彫刻の形が崩れることがある。
- LIVE のカボチャは顔に合わせた変形ではなく剛体の3Dカボチャ（彫刻の形だけが表情で変わる）。髪や手によるオクルージョンは扱わない。
- LIVE のカボチャは頭全体を覆う大きさのため、彫刻面は実際の顔より約0.5顔幅手前にある。顔を大きく横に向けると、彫刻の目と実際の目の位置に少し視差が出る（両目の中点は常に一致）。
- 髪のボリュームが非常に大きい場合（大きく広がった髪・高いまとめ髪など）は、上の角から髪がはみ出すことがある。
- 書き出しの 9:16 は画面の縦横比と異なる場合があり、LIVE では左右/上下の見える範囲がプレビューと少し変わる（顔とカボチャの位置関係は同一）。
- 写真入力からの LIVE 合成は非対応（写真 → MAKE のみ）。
- カメラは MAKE の結果表示中もバックグラウンドで動作し続ける（撮り直しを速くするため。推論と描画は停止）。
- MAKE でスタンプを貼っている間は、保存される完成ポーズの静止画の上で編集する（3Dの回転表示には戻らない。スタンプを全部消して「完了」すると戻る）。
- スタンプの文字はシステムの太字フォント（Arial Black など）で描き、幅だけを揃えている。端末によって字形は少し変わるが、画面と保存PNGは同じフォントで描かれる。
- スタンプを貼った状態では、画像の長押し保存（スタンプなしの元画像になってしまう）を無効にしている。保存は「保存」ボタンを使う。
- `npm audit` で `braces`・`node-forge` の high が出るが、どちらも Nuxt のビルド/開発ツール経由の推移的依存で、修正版が未公開（最新版が該当）。本番の `.output` には含まれない。`npm audit fix --force` は Nuxt をダウングレードするため実施していない。

## 9. ロリポップ！デプロイナウへの公開手順
> デプロイは別途の明示的な指示があるまで実行しない。以下は準備済みの手順。
> CLI の公式ドキュメント: https://deploy.lolipop.jp/docs/cli ・ Nuxt: https://deploy.lolipop.jp/docs/frameworks/nuxt

前提
- Node.js 22.12 以上（CLI の要件）。本プロジェクトのビルドには 22.19 以上を推奨。
- Nuxt の既定プリセット（`node-server`）のまま。Deploy Now の Nuxt 既定値は install `npm ci --ignore-scripts` / build `npm run build` / output `.output` で、本プロジェクトはそのまま動く（WASM コピーは build スクリプト内で実行）。
- 環境変数・シークレットは不要。

手順
```bash
npm run test && npm run typecheck && npm run build   # ローカルで確認
npm install -g lolipop                               # もしくは npx lolipop ...
lolipop frameworks list                              # "nuxt" があることを確認
lolipop deploy --name pumpkin-me --framework nuxt    # 初回（未ログインならブラウザでログイン）
# 2回目以降: プロジェクトをリンクして lolipop deploy
lolipop project link <project-id>
lolipop deploy
```
